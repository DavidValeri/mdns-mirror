# Test and promote the same image digest, and keep test tools out of the shipped image

The release builds the runtime image once, pushes it to a candidate tag, runs the smoke test and the full suite against that digest, and then adds the version tags to the same digest. We chose this over rebuilding the image at release time, because a rebuild can produce bytes that differ from the ones tested, even from the same commit. The shipped image holds only the runtime, and the tests run from outside it, through a throwaway container from the same image. We rejected a test stage in the shipped image, because test tools and test code would then ship to production. The consequence is that the image cannot be tested in place for everything, so the suite overrides the entrypoint and needs extra capabilities for its namespace tests.
